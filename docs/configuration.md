# Настройка

Все параметры задаются переменными окружения; для удобства их можно положить в файл `.env`.
Шаблон лежит в `.env.example`, пример для systemd: [deploy/tg-secretary.env.example](../deploy/tg-secretary.env.example).
Связанные документы: [развёртывание](deployment.md), [архитектура](architecture.md).

## Загрузка `.env` и приоритеты

- Файл `.env` ищется в рабочей директории процесса. Если файла нет, это не ошибка.
- Приоритет у окружения: переменная, уже заданная в окружении процесса, не перезаписывается значением из `.env`
  (даже если она задана пустой).
- Формат строк: `KEY=VALUE`. Пустые строки и строки, начинающиеся с `#`, пропускаются. Допустим префикс `export `.
  Пробелы вокруг ключа и значения обрезаются, парные одинарные или двойные кавычки вокруг значения снимаются.
  Комментарий в конце строки не поддерживается: он станет частью значения.
- Внутри Docker и systemd `.env` обычно не используется: переменные передаются через `--env-file` или `EnvironmentFile=`.
- Значения, указанные как пустые, считаются незаданными и заменяются значением по умолчанию
  (для `TG_DB_PATH`, `MCP_ADDR`, `WEB_UI`, `TG_ALLOW_SEND`).

## Переменные окружения

| Переменная | Тип | По умолчанию |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | строка | пусто |
| `TELEGRAM_API_URL` | URL | `https://api.telegram.org` |
| `TG_DB_PATH` | путь | `data/secretary.db` |
| `TG_ALLOWED_CHATS` | список чисел | пусто (все чаты) |
| `TG_ALLOW_SEND` | bool | `false` |
| `MCP_ADDR` | `host:port` | `127.0.0.1:8080` |
| `MCP_AUTH_TOKEN` | строка | пусто |
| `WEB_UI` | bool | `true` |
| `TG_AVATARS` | bool | `true` |
| `TG_IMPORT_DIR` | путь или `off` | `data/import` |

Булевы значения разбираются как в Go (`strconv.ParseBool`): `1`, `t`, `T`, `TRUE`, `true`, `True`
и `0`, `f`, `F`, `FALSE`, `false`, `False`. Любое другое значение даёт ошибку запуска.

### TELEGRAM_BOT_TOKEN

Токен бота от @BotFather. Обязателен для `serve`, `bot` и `stdio -with-bot`, а также при `TG_ALLOW_SEND=true`.
Для `stdio` без бота и без отправки не нужен.

```
TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
```

### TELEGRAM_API_URL

Адрес Bot API. Нужен, только если вы запускаете собственный сервер Bot API. Завершающий `/` отбрасывается.

```
TELEGRAM_API_URL=http://localhost:8081
```

### TG_DB_PATH

Путь к файлу SQLite. Относительный путь считается от рабочей директории процесса.
Каталог создаётся автоматически (права `0700`), файл получает права `0600`.
Если несколько процессов (`bot` и `stdio`) работают с одной базой, задавайте абсолютный путь.

```
TG_DB_PATH=/var/lib/tg-secretary/secretary.db
```

### TG_ALLOWED_CHATS

ID чатов через запятую, из которых разрешено сохранять сообщения. Пробелы вокруг чисел допустимы.
Пустое значение означает «все чаты, где есть бот». Нечисловое значение даёт ошибку запуска.
ID групп и каналов отрицательные, например `-1001234567890`. Узнать ID уже известных чатов можно инструментом
[`list_chats`](mcp-tools.md#list_chats) или в [веб-интерфейсе](web-ui.md).

```
TG_ALLOWED_CHATS=123456789,-1001234567890
```

Фильтр действует на сохранение новых и изменённых сообщений. Уже сохранённые сообщения он не удаляет.

### TG_ALLOW_SEND

Если `true`, MCP-сервер регистрирует инструмент [`send_message`](mcp-tools.md#send_message), а агенты могут писать
от имени бота (в бизнес-чате от имени владельца аккаунта). По умолчанию выключено. Требует `TELEGRAM_BOT_TOKEN`.

### MCP_ADDR

Адрес, на котором слушает HTTP-сервер (команда `serve`). Используется для `/mcp`, веб-интерфейса и `/healthz`.
Если адрес не loopback, нужен `MCP_AUTH_TOKEN` (см. [аутентификация](#аутентификация)).

```
MCP_ADDR=0.0.0.0:8080
```

### MCP_AUTH_TOKEN

Общий токен доступа к `/mcp` и веб-интерфейсу. Сгенерировать можно так:

```bash
openssl rand -hex 32
```

### WEB_UI

`false` отключает веб-интерфейс. Тогда `/` вернёт 404, а `/mcp` и `/healthz` продолжат работать.

### TG_AVATARS

Если `true`, бот скачивает аватарки чатов (160×160) и хранит их в базе; веб-интерфейс показывает их
в списке чатов. `false` отключает загрузку: уже сохранённые картинки остаются, новые не запрашиваются.
Подробности: [web-ui.md](web-ui.md#аватарки).

### TG_IMPORT_DIR

Каталог, из которого инструмент [`import_chat_export`](mcp-tools.md#import_chat_export) может читать
JSON-экспорты личных чатов, слишком большие для передачи в самом вызове (больше 8 МБ).
Относительный путь считается от рабочего каталога. При запуске каталог создаётся (права `0700`), если его нет.
Значение `off` убирает инструмент импорта у агентов целиком.

### Что проверяется при запуске

- `TELEGRAM_BOT_TOKEN` не задан, а бот запускается: ошибка `TELEGRAM_BOT_TOKEN is not set`.
- `TG_ALLOW_SEND` включён без токена: ошибка `TG_ALLOW_SEND requires TELEGRAM_BOT_TOKEN`.
- HTTP-сервер запускается без `MCP_AUTH_TOKEN` на не-loopback адресе: отказ запуска.
- Неверные значения `WEB_UI`, `TG_ALLOW_SEND`, `TG_ALLOWED_CHATS`: ошибка с названием переменной.

## Режимы запуска

| Команда | Бот | MCP по HTTP | Веб-интерфейс | MCP по stdio |
| --- | --- | --- | --- | --- |
| `tg-secretary serve` | да | да | да (`WEB_UI`) | нет |
| `tg-secretary serve -no-bot` | нет | да | да (`WEB_UI`) | нет |
| `tg-secretary bot` | да | нет | нет | нет |
| `tg-secretary stdio` | нет | нет | нет | да |
| `tg-secretary stdio -with-bot` | да | нет | нет | да |

Остальное:

- `tg-secretary version` печатает версию и выходит; `tg-secretary help` (а также `-h`, `--help`) печатает справку.
- Без команды печатается справка и процесс завершается с ошибкой.
- Флаги указываются после команды: `tg-secretary serve -no-bot`.
- Логи всегда идут в stderr (в режиме `stdio` stdout занят протоколом MCP).
- Процесс завершается по SIGINT или SIGTERM.
- Типичные схемы: один процесс `serve`; либо `bot` (демон) плюс `stdio` для каждого агента, который сам запускает
  MCP-сервер; либо `serve -no-bot` рядом с отдельным `bot`. Бот при этом всегда только в одном процессе.

## Аутентификация

Относится к HTTP-серверу (`serve`). Режим `stdio` не использует токен: доступ определяется тем, кто запустил процесс.

- Если `MCP_AUTH_TOKEN` пуст, аутентификации нет. Это допустимо только для loopback-адресов:
  `localhost`, `127.0.0.0/8`, `::1`. Адрес вида `:8080` или `0.0.0.0:8080` без токена запустить нельзя.
- Если токен задан, он требуется для `/mcp` и для всего, что отдаёт веб-интерфейс (`/`, `/static/`).
  Принимаются два способа:
  - заголовок `Authorization: Bearer <токен>` (для агентов);
  - HTTP Basic с любым логином и токеном в качестве пароля (для браузера).
- Сравнение токена выполняется за постоянное время.
- При неверных данных возвращается `401 unauthorized` с заголовком `WWW-Authenticate: Basic realm="tg-secretary"`.
- `/healthz` отвечает `ok` без аутентификации и подходит для проверки живости.
- Токен передаётся в открытом виде, поэтому вне localhost нужен TLS, см. [раздел о прокси](deployment.md#обратный-прокси-и-tls).
