# Вклад в проект

Спасибо за интерес. Ниже минимум, который нужен, чтобы изменение было принято.
Подробности про устройство и релизы: [docs/development.md](docs/development.md), [docs/architecture.md](docs/architecture.md).

## Сборка и проверки

Нужен Go 1.26 или новее.

```bash
make build
```

```bash
make lint test
```

`make lint` проверяет `gofmt` и `go vet`, `make test` запускает `go test -race ./...`. CI выполняет то же самое.

## Стиль

- [Uber Go Style Guide](https://github.com/uber-go/guide/blob/master/style.md);
- код отформатирован `gofmt`, `go vet` без замечаний;
- комментарии к пакетам и экспортируемым идентификаторам;
- без новых зависимостей, если задача решается стандартной библиотекой.

## Pull request

- Одно изменение на один PR, с понятным описанием: что и зачем.
- Для исправлений и новой функциональности добавляйте тесты.
- Если меняется поведение, видимое пользователю (инструменты MCP, переменные окружения, схема SQLite, веб-интерфейс),
  обновите документацию в `docs/` и [CHANGELOG.md](CHANGELOG.md) (раздел Unreleased).
- Не включайте в PR токены, базы и личные переписки, в том числе в тестовых данных и логах.
- О проблемах безопасности сообщайте владельцу репозитория напрямую, а не в публичном issue.

## Сообщения об ошибках

В issue приложите версию (`tg-secretary version`), команду запуска, соответствующие строки лога
(без токенов) и шаги воспроизведения.
